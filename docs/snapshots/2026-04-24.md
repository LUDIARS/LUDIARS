## メタ / インフラ

### LUDIARS (meta)

- **概要**: LUDIARS 組織全体のメタリポジトリ。各サービス
  (Cernere/Actio/Nuntius/Imperativus 等) の統合イメージ、
  Docker Compose 構成、All-in-One 初期化スクリプト、CI/CD
  ワークフロー (自動ホスト統合テスト) を管理。`ServiceMap.md` で
  全 12 サービス・3 クライアント・3 ツール計 18 リポジトリを
  カタログ化。
- **完成度**: 70% — CI パイプライン・初期化スクリプト機能、
  ServiceMap ドキュメント完成。個別サービスは計画中・未着手も多い
- **完成している機能**:
  - All-in-One Docker Compose 設定 (自動起動・セルフホスト CI 対応)
  - 初期化・セットアップスクリプト (`setup.mjs`)
  - GitHub Actions CI (Cernere / Actio / Nuntius / Imperativus 統合テスト)
  - `ServiceMap.md` (全サービスの役割・技術・依存関係を表形式・図で記載)
  - 自動ホスト CI ワーカセットアップドキュメント
- **未完成 / 次のタスク**:
  - 全 12 サービスの実装並行
  - クロスサービス認証フロー自動テスト
  - 分散トレーシング・監視統合
  - デプロイ自動化 (本番・ステージング)
  - 各サービス個別 README、仕様書の整備
- **主要依存**: Docker Compose v2 / PostgreSQL 17 / Redis 7 / Infisical

### infra

- **完成度**: 90% — 本番利用可。全 LUDIARS マイクロサービスの
  データベース・キャッシュ層を統一提供。マイグレーション自動化・
  監視ツール統合済み
- **完成している機能**:

  - `pgweb` / `RedisInsight` / MinIO Console / MailHog UI (各ポート用意)
  - 自動マイグレーション (SQL + Drizzle ORM 両対応)
  - `_migration_history` テーブルでトラッキング
  - Windows cmd.exe 対応 (cross-env 環境変数設定)
  - MailHog SMTP キャッチャー
- **未完成 / 次のタスク**:
  - メトリクス監視 (Prometheus・Grafana)
  - バックアップ・復旧自動化
  - 本番環境 Kubernetes 化
  - マルチリージョン対応
  - パフォーマンスチューニング (接続プール)
- **主要依存**: Docker・Node.js。SQL/Drizzle 戦略の切り替え対応済み

### Codex

- **概要**: 検証可能な署名済イベント台帳。モバイル軽量クライアント
  前提、Ethereum の検証モデルを簡略化した LUDIARS 汎用基盤。
  ゲーム権利・アセット所有・出席確定を統一的に記録・検証可能にする。
- **完成度**: 45% — 設計ドラフト (v0.10, 2026-04-23)。
  M0 ~ M9 実装完了 (core・crypto・state・consensus・sync・light・
  node・demo・FFI)。本実装着手段階。
- **完成している機能**:
  - `codex-core`: Event・Block・署名・構造体定義
  - `codex-crypto`: ed25519 + blake3 (Synergos 非依存の独立実装)
  - `codex-state`: sorted-key merkle tree・proof・nonce・handler
  - `codex-consensus`: session/committee mode 両対応・PoA finality
  - `codex-node` / `codex-sync` / `codex-light`: full/light client
  - `codex-bench` (criterion) + `codex-ffi` (C ABI + cbindgen)
- **未完成 / 次のタスク**:
  - プロダクション硬化 (NEP + state snapshot + dynamic namespace)
  - ValidatorSetChange 予告制・ValidatorSlash 即時除名 (v1)
  - Tessera・Curare 権利実装の統合
  - per-chain block interval (achievement 用長 interval)
  - state pruning 戦略 (25GB / 10⁸ entries 対応)
- **主要依存**: Synergos (ed25519・blake3・QUIC)

  サーバー。OAuth / パスワード / MFA 認証、WebSocket 常時接続

  LUDIARS 全サービスの認証基盤。
- **完成度**: 85% — メインの認証・セッション・WebSocket リレー基盤が
  実装済み。周辺ユースケースの拡張中。
- **完成している機能**:
  - JWT/OAuth 認証 (GitHub・Google) + パスワード認証 (bcrypt)
  - MFA 対応 (TOTP・SMS・Email)
  - Redis TTL 7 日のセッション管理 + Ping/Pong 生存確認
  - WebSocket モジュールベースのコマンドディスパッチ
    (organization/member/user/project)
  - 多層防御 (Cookie 検証→TTL→状態→権限) とリレーメッセージング

### Nuntius

  - BullMQ キュー (時間指定・優先度・リトライ付き)

  - Cernere Composite 認証 (admin UI)

- **未完成 / 次のタスク**:

- **主要依存**: BullMQ (Redis)、Drizzle ORM (PostgreSQL)、
  Cernere、nodemailer (Email)、AWS SNS (SMS)

> 両リポジトリが実質同じプラットフォームを指すので統合して記述。

  (Event)」「タスク (Task)」を中心に、カレンダー・PM・自動
  スケジューラなど複数モジュールが機能を拡充する JIRA 型
  プラットフォーム。
- **完成度**: 85% — Module SDK Phase 1、プラグイン駆動アーキテクチャ
  確立。Event / Task コア、カレンダー・グループ・PM・学校
  カリキュラム、スマートスケジューラ主要モジュール完成。
- **完成している機能**:
  - Event (時間拘束)・Task (要件ベース) コア概念
  - Module SDK (`@ludiars/schedula-sdk` の `defineModule`)
  - JWT + Cernere 認証 + ユーザ管理
  - Drizzle ORM マルチ DB 対応 (SQLite / PostgreSQL / MySQL)
  - カレンダー + MyPlan (週間ルーティーン)
  - PM (GitHub / Notion 同期・コンフリクト解決・分析)
  - 学校カリキュラム管理 (M1) + マイグレーション
  - DP ベーススマートスケジューラ
  - Holiday 管理・Voting (日程調整)
  - 施設予約・通知モジュール群
- **未完成 / 次のタスク**:

  - GitHub Packages publish CI
  - `curriculum-scheduler` module (Phase 2.0 まで)
- **未完成 / 次のタスク**:
  - release ブランチ自動生成 CI (`module_list.md` 集約)

  - `module/_shared` 共通ユーティリティブランチ

- **主要依存**: `@ludiars/schedula-sdk` バージョニング
